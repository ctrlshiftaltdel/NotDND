# tests/ · 测试约定

本目录是回归测试。跑全部：

```bash
bash tests/run_all.sh        # 收集 tests/test_*.py，串行执行，汇总退出码
```

也可以单独跑某一个：`python3 tests/test_xxx.py`。脚本自己的退出码就是判据
（0 = 通过，非 0 = 失败）。

## 写一个测试脚本

- 文件名 `test_*.py`；`run_all.sh` 按这个前缀收集，未见到的不会被跑。
- 零第三方**运行时**依赖；测试期依赖能不加就不加，新增的要在 PR 说明。
- 断言要**真跑**出来，不要对着实现抄一遍——抄出来的断言只会证明「代码还会
  被抄一遍」。
- 需要服务时，起在**自己的随机端口 + 自己的临时存档目录**；退出时务必收摊
  （进程与目录都要清），失败路径也要清。
- 只清理**能证明是测试**的遗留进程：`bash tests/cleanup_servers.sh`
  （判据是「临时存档目录 + 非服务端口」两条，详见脚本顶部说明）。

## 概率型断言守则

涉及随机（掷骰、遇敌、抽签……）的断言最容易偶发变红。动手前先问三句：

1. **「这一轮给了几次有效机会？」** —— 断言命中率之前先数清独立机会的个数。
   只有一次机会就别断言「大概会中」，那是在赌运气。
2. **循环开新局** —— 需要「至少命中一次」时，别硬等一轮；多开几局直到目标
   事件出现（设一个上限，超了才判失败）。
3. **两条合法分支都收** —— 随机结果的两条合法路径要都能通过；只认其中一条，
   等于把概率当成确定性。

更稳的做法是**进程内注入可控随机**（直接替换被测函数里的随机源），
把「随机」从测试里彻底拿掉——这样断言的是逻辑，不是运气。

## 存档目录「问服务端」

测试常在**子进程**里起服务，而子进程读不到测试进程后来才设的环境变量。
所以别在测试里猜存档写到了哪里：服务端会把 `save_dir` 随存档列表接口回传，
测试据此定位（见 `notdnd_web.py` 的说明）。

## 浏览器测试

浏览器用例依赖**无头浏览器**和**WebSocket 客户端**，共用助手 `tests/_cdp.py`
（CDP-over-WebSocket 最小封装）。**缺任何前置条件就优雅跳过**：打印一行
`skip：…（退出码 0）` 并以 0 退出，绝不判失败——CI 机器常常没有图形环境，
「跑不了」不该等于「坏了」。

三个前置条件：有 `static/index.html`、有 WebSocket 客户端、有可用浏览器
（可用环境变量 `NOTDND_CHROME` 指定浏览器路径）。示例见
`tests/test_ui_smoke.py`。
