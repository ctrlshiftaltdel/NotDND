# 02B · 构建引擎（Forge Engine）

**核心骰：d10 骰池 ＋ 成功计数　｜　口味：高深度，构筑与资源运筹为核心**

> 战术引擎回答"这一击能不能打中"。构建引擎回答"我这套东西能不能跑起来"。
> 如果你的乐趣在于**计算、配装、资源循环、把一套构筑推到极限**，这是属于你的引擎。
> 代价是：结算步骤更多，需要玩家投入更多注意力。新手团建议先跑战术引擎。

## 一、骰池与成功

构建引擎不使用单个 d20，而是**一次掷一把骰子**。你的能力越强，手里的骰子越多、越大。

### 骰池的构成

```
骰池 = 主属性枚数 + 技能熟练枚数 + 临时加成枚数
```

- **主属性枚数** = 该属性的值本身（见 `CORE` 第 1 节量表）。属性 5 就是 5 枚骰。
- **技能熟练枚数** = 熟练加值的一半（向上取整）：熟练 +2 → +1 枚；+3 → +2 枚；+4 → +2 枚。
- **技能专精** = 额外 +1 枚。
- **临时加成** = 协助、态势、场地要素等提供的额外骰子，通常 1–3 枚。

> **注意**：构建引擎里的"加值"几乎都转换为**骰子枚数**，而不是固定数字。这让每一次加成都看得见、数得着。

### 成功阈值

骰池里的每一枚骰，**点数 ≥ 5 记作 1 次成功**。

| 骰子 | 单骰成功率 |
|---|---|
| d6 | 33% |
| d8 | 50% |
| d10 | 60% |
| d12 | 67% |

**默认骰面为 d10。** 角色的骰面通过骰阶升级提升（见第 3 节）。

### 难度 = 需求成功数

构建引擎的难度不写成 DF，而写成**需要多少枚成功**。

| 需求成功数 | 名称 | 战术引擎对应 DF |
|---|---|---|
| 1 | 平凡 | 8 |
| 2 | 简易 | 10 |
| 3 | 常规 | 12 |
| 4 | 有挑战 | 14 |
| 5 | 困难 | 16 |
| 6 | 严峻 | 18 |
| 8 | 极限 | 20 |
| 10 | 传说 | 24 |

### 判定的完整形式

```
需求成功数 N（由导引者宣布）
玩家掷 [骰池] 枚骰（面值由骰阶决定）
清点 ≥5 的骰子数量 S
结果 = S - N
```

## 二、五档结果梯度

构建引擎使用与战术引擎相同的五档命名，但用成功数的差来区分：

| S − N | 档位 | 后果 |
|---|---|---|
| ≥ +3 | **凯旋** Triumph | 达成 ＋ 额外收益。**额外获得 2 点动量** |
| +1 ~ +2 | **成功** Success | 达成。**获得 1 点动量** |
| 0 | **险成** Narrow | 达成，但附带一个代价。**获得 1 点动量** |
| −1 | **挫败** Failure | 未达成，情况恶化。**获得 1 点动量**（安慰性补偿：失败也要给下一次铺路） |
| ≤ −2 | **灾难** Catastrophe | 未达成 ＋ 显著麻烦。**获得 2 点动量**（这是为了让玩家在低谷后能够反击） |

> **动量反向补偿的设计说明**：构建引擎刻意让失败也给予动量，因为它的资源循环是建立在"动量消耗 → 反哺成功"之上的。若失败一无所获，玩家会陷入死亡螺旋。这是两套引擎在手感上最大的不同。

### 全骰皆负的情况

当骰池中**没有任何一枚骰达到阈值**时，无论需求成功数是多少，都至少视为 **−1（挫败）**，且获得 1 点额外动量。

### 最大值爆发

任何一枚骰掷出**最大面值**（10 面上的 10，12 面上的 12 等）时，该骰记作 **2 次成功**。这是高风险设计带来的天然回报。

## 三、骰阶与专精

**骰阶（Die Rank）** 决定你池子里骰子的大小。这是构建引擎最主要的纵向成长轴。

| 骰阶 | 骰面 | 达成方式 |
|---|---|---|
| I | d6 | 未受训的属性（新手角色） |
| II | d8 | **默认起始值**：角色所有骰阶为 d8 |
| III | d10 | **标准手法**：每项 +1 枚对该属性的骰阶提升 |
| IV | d12 | 需要投入大量构建点 |
| V | d20 | 极限成就，通常在 8 级以后才可能触及 |

> 起始角色的所有骰阶为 **d8**（骰阶 II）。这保证 1 级角色的每项判定至少有 50% 的单骰成功率。

### 属性 ↔ 骰阶的对照

一个属性 6、骰阶 III 的角色，在使用该属性时掷 **6 枚 d10**。期望成功数约 3.6，足以应付"困难（需要 5）"以外的多数任务。

### 期望成功数速查

| 骰池 | d8 | d10 | d12 |
|---|---|---|---|
| 2 枚 | 1.0 | 1.2 | 1.3 |
| 3 枚 | 1.5 | 1.8 | 2.0 |
| 4 枚 | 2.0 | 2.4 | 2.7 |
| 5 枚 | 2.5 | 3.0 | 3.3 |
| 6 枚 | 3.0 | 3.6 | 4.0 |
| 7 枚 | 3.5 | 4.2 | 4.7 |
| 8 枚 | 4.0 | 4.8 | 5.3 |
| 10 枚 | 5.0 | 6.0 | 6.7 |

> **给玩家的配装建议**：一枚额外骰子约等价于 +0.5 期望成功；一次骰阶提升约等价于 +20% 每骰成功率。**前期加骰子，中期升骰阶，后期两者结合。**

## 四、动量 Momentum

**动量**是构建引擎的核心资源：衡量"当前局势站在谁这边"。它是一个**团队共享池 + 个人溢出**的混合设计。

```
动量池 = 共享池（起始 0，上限 10） ＋ 每人各自的持有上限 5
```

### 获取动量

| 来源 | 动量 |
|---|---|
| 判定结果为成功 | +1 |
| 判定结果为凯旋 | +2 |
| 判定结果为灾难 | +2 |
| 队友的协助动作生效 | +1 |
| 你承受了一次超过 10 点的伤害 | +1 |
| 你演出了符合角色驱动、且对自己不利的抉择 | +1（导引者判定） |
| 敌人发生一次士气崩溃 | +2（全队） |

### 花费动量

动量可以在**任何时候**花费，包括他人的回合：

| 花费 | 效果 |
|---|---|
| **1 点 — 补强** | 向正在进行的判定追加 1 枚骰（可多次，上限 3 枚） |
| **2 点 — 重掷** | 重掷池中所有未成功的骰子一次 |
| **2 点 — 升阶** | 本次判定中，把所有骰视为高一阶（d8→d10→d12） |
| **1 点 — 改写失败** | 把一次 −1 结果提升为 0（险成） |
| **3 点 — 额外行动** | 在当前时刻获得额外 1 AP |
| **2 点 — 刷新** | 一项本场景已消耗的能力可以再用一次 |
| **1 点 — 连携增强** | 下一次连携完成时，额外获得 1 层连锁 |

### 动量清零

**每个场景结束时，共享池中的动量清零。** 未使用的动量不会累积到下一幕——这逼迫玩家在当下就用掉它，形成紧凑的资源节奏。

> 这是设计上的刻意选择：动量不是储蓄，而是节奏。想要长期资源的角色应当投资"符纹插槽"而非囤积动量。

## 五、应力 Stress 与超载

如果说动量是构建引擎的油门，**应力就是它的温度计**。

### 应力上限

```
应力上限 = 体魄 + 心智 + 5
```

典型范围在 13–21 之间。应力从 0 开始累积。

### 获得应力的方式

| 行为 | 应力 |
|---|---|
| **超载一次判定**（宣布后重掷全池，取第二次结果） | +2 |
| 受到一次超过自身活力上限 1/4 的伤害 | +1 |
| 连续第二次宣布超载（同一场景内） | +3 |
| 使用超出自身能力等级的资源（强行动用未掌握的能力） | +2 |
| 处于濒危状态 | +2 |

### 应力的惩罚

| 应力占上限比例 | 惩罚 |
|---|---|
| 0–49% | 无 |
| 50–79% | 所有判定骰池 −1 枚；描述上表现出紧张、急促、手抖 |
| 80–99% | 骰池 −2 枚；每次开始回合需通过耐受判定（需求成功 3），失败则失去 1 AP |
| 100% | **崩溃** |

### 崩溃 Overload Event

应力达到上限时立即触发：

1. 角色**失去本回合所有 AP**，且必须演出崩溃的具体表现（导引者与玩家共同决定，玩家优先）；
2. 获得 3 层【疲惫】与 1 点负担；
3. 所有进行中的超载效果立即中断；
4. 应力回落至上限的 50%。

> **崩溃不是惩罚，是节奏装置。** 它让"要不要再超载一次"成为一个真正的选择，让玩家自己管理自己的英雄时刻。

### 降低应力

| 方式 | 降低 |
|---|---|
| 短歇 | −2 |
| 长歇 | −4（在安全据点 −6） |
| 完成一次角色驱动相关的目标 | −2 |
| 特定能力／道具 | 见具体描述 |

## 六、战斗中的应用

构建引擎的战斗流程与内核一致（AP、破韧、连携、场地要素全部保留），只有**攻击如何结算**不同。

### 攻击结算

```
1. 选择目标，支付 AP
2. 掷攻击骰池 vs 目标的「闪避需求」（见下表）
3. 依据成功数之差，确定命中的次数，而非简单的命中/落空
4. 每次命中造成基础伤害
5. 追加效果由「成功数溢出」提供
```

### 目标的闪避需求

| 目标类型 | 需求成功数 |
|---|---|
| 静止／无防备 | 2 |
| 标准敌人 | 3 |
| 灵活／远程专长 | 4 |
| 高防护目标 | 5 |
| 重甲单位 | 6 |

目标的掩体、态势与其他位置优势会增加这个需求成功数（每项 +1，最多 +2）。

### 命中次数与伤害

设 **D = 成功数 − 闪避需求**

| D | 命中结果 |
|---|---|
| ≥ +4 | **贯穿打击**：造成 3 次基础伤害；目标获得 3 层【失衡】 |
| +2 ~ +3 | **多重命中**：造成 2 次基础伤害 |
| 0 ~ +1 | **命中**：造成 1 次基础伤害 |
| −1 | **擦过**：造成一半伤害（向下取整） |
| ≤ −2 | **落空**：无伤害 |

> 注意这里的差别：**构建引擎的攻击可以有多次命中**。这让"多骰池射手"在装备成型后能打出非常可观的单回合输出，而这是他以长期构筑换来的。

### 溢出成功可以购买附加效果

当一次攻击的 D ≥ +2 时，玩家可以将多余的成功用于购买附加效果，每 +1 次成功换取下列一项：

- 削减目标 3 点韧性；
- 对目标施加一个 1 层状态；
- 把这次攻击的伤害类型临时转换（例如转为另一个标签以针对弱点）；
- 命中一个相邻的第二目标（造成一半伤害）。

## 七、超载连锁

当一次判定的成功数**达到需求成功数的两倍**（且至少盈余 3 枚）时，触发**超载连锁**。

超载连锁时，玩家可以立即选择下列一项，**不消耗任何资源**：

1. 立即追加一个 1 AP 的动作；
2. 刷新一项本场景已消耗的能力；
3. 把这次判定的结果向上升一档（险成 → 成功 → 凯旋）；
4. 为团队共享池注入 2 点动量。

> 超载连锁每名角色**每个场景限一次**。它是奖励"把一套构筑推到极致"的机制，也是构建引擎玩家的爽点来源。

## 八、符纹插槽系统

这是构建引擎区别于战术引擎的**核心系统**，也是"深度构筑"的乐趣来源。

### 概念

角色的每一个能力（Faculty）都是一个"基底"。基底本身的效果是固定的，但你可以把**符纹（Glyph）**嵌入它的插槽，从而改变这个能力的行为。

> 一个能力最多拥有 **3 个插槽**。同一枚符纹可以安装在一个能力上，也可以被拆下装到另一个能力上（每个场景开始时可以调整一次）。

### 插槽的获得

| 来源 | 插槽 |
|---|---|
| 起始 | 1 个 |
| 等级 4 | +1 |
| 等级 7 | +1 |
| 等级 10 | +1 |
| 用构建点购买（每个 3 BP，上限 2 个） | +1 |

> **重要**：插槽的总数决定了你能同时"激活"多少枚符纹。插槽不足时，玩家必须做出取舍——这正是构建的乐趣。

### 符纹的获得

- 起始角色得 **2 枚**（自选）；
- 每次升级可获得 1 枚新符纹（消耗 2 BP）；
- 世界模组中的特定地点、导师与任务奖励会提供稀有符纹。

### 符纹的结构

```
【符纹名】（等级 N）
  效果：<改变能力的行为>
  代价：<嵌入后这个能力带来的副作用>
```

> **每条符纹都有代价。** 这不是为了惩罚玩家，而是为了让"堆满符纹"不是无脑最优解。真正的构筑艺术在于：**找到那些对你的构筑而言代价几乎不痛的符纹。**

## 九、构建点与成长

构建引擎的成长单位叫**构建点（Build Point, BP）**。

```
每升一级 → 获得 2 BP
```

（战术引擎每级给 1 个成长选择；构建引擎给 2 点，因为它的每一项都要单独投资。）

### 花费表

| 项目 | BP | 备注 |
|---|---|---|
| **属性 +1** | 3 | 单项上限 10；通过此方式每项最多 +4 |
| **某属性的骰阶 +1 阶** | 4 | 上限 V 阶（d20） |
| **获得一项新技能熟练** | 2 | 该技能的骰池额外 +1 枚 |
| **技能升级为专精** | 2 | 需已有熟练；骰池再 +1 枚 |
| **获得一枚新符纹** | 2 | 永久拥有，可随时调整安装位置 |
| **新增一个插槽** | 3 | 最多额外购买 2 个 |
| **一项能力等级 +1** | 2 | 伤害／范围／持续时间提升 |
| **掌握一项新能力** | 3 | 从所属职途的能力列表中选择 |
| **专注上限 +2** | 1 | 无上限限制 |
| **应力上限 +2** | 1 | 无上限限制 |
| **场景起始动量 +1** | 2 | 最多 +3 |
| **越界学习**：跨流派学一项能力 | 5 | 每角色限 2 次 |

### 起始资源分配（1 级）

```
· 属性：按 CORE 第 1 节方法确定（所有骰阶为 d8）
· 2 项技能熟练 + 1 项技能专精
· 1 个插槽
· 2 枚自选符纹
· 3 项能力（其中 1 项可装符纹）
· 起始 BP：0（后续每级 2 BP）
```

### 三种典型构筑路线

为了帮助新手理解这套系统，这里给出三条被验证过的路线：

**「重炮」路线**：把插槽全部装给一个伤害能力，堆叠增幅类与代价类符纹；属性投资到相关的心智或力道上；相信一击定胜负。**风险**：弹药（专注）消耗极快。

**「织网」路线**：把效率类符纹堆在一起，让能力的消耗降到最低，然后用节省下来的资源反复使用；属性投资到骰池规模上；靠多次行动取胜。**风险**：单点爆发不足，遇上高防护目标会很吃力。

**「共鸣」路线**：投入连锁类与转化类符纹，追求“一次判定引发多重效果”；高度依赖队友先创造出状态再引爆。**风险**：单打独斗时大幅削弱，这是一条必须依赖团队的路线。

## 十、符纹库

**【可替换】** 以下 28 枚为通用符纹。世界模组会追加各自特有的符纹。

### 增幅类

| 符纹 | 等级 | 效果 | 代价 |
|---|---|---|---|
| **强袭符** | I | 伤害 +3 | AP 消耗 +1 |
| **广域符** | I | 范围半径 +3 米 | 专注消耗 +1 |
| **穿透符** | I | 无视目标 3 点防护与轻掩体 | 需求成功数 +1 |
| **持续符** | I | 持续时间 +1 回合 | 该能力无法在此期间被刷新 |
| **多重符** | II | 额外命中一次（第二次伤害减半） | 应力 +1 |

### 效率类

| 符纹 | 等级 | 效果 | 代价 |
|---|---|---|---|
| **节俭符** | I | 专注消耗 −1（最低为 1） | 伤害骰降一阶 |
| **迅捷符** | I | AP 消耗 −1（最低为 1） | 需求成功数 +1 |
| **回充符** | II | 每场景一次，使用后立刻刷新一个已消耗的能力 | 应力 +2 |
| **轻盈符** | I | 不再需要语言或手势成分（可沉默施放） | 范围 −3 米 |
| **共生符** | II | 命中同伴时为团队注入 1 点动量 | 伤害 −2 |

### 转化类

| 符纹 | 等级 | 效果 | 代价 |
|---|---|---|---|
| **燃烬符** | I | 伤害转为【火焰】并引燃可燃物 | 场景中未受控的可燃物亦会被引燃 |
| **霜噬符** | I | 伤害转为【寒霜】，并使目标获得 1 层【迟滞】 | 伤害 −2 |
| **雷引符** | I | 伤害转为【电击】，并传导至相邻的一个目标（一半伤害） | 在导电环境中你自己也会受影响 |
| **音爆符** | I | 伤害转为【声波】，并完全无视掩体 | 发出巨响，暴露所有人位置 |
| **熵染符** | II | 伤害转为【熵蚀】，并使目标获得 1 层【熵染】 | 你自己获得 1 点应力 |

### 触发类

| 符纹 | 等级 | 效果 | 代价 |
|---|---|---|---|
| **破绽符** | I | 命中后目标获得 1 层【破绽】 | 需求成功数 +1 |
| **震退符** | I | 命中后推动目标 2 米 | 伤害 −1 |
| **迟缓符** | I | 命中后目标移动减半，持续一回合 | 专注消耗 +1 |
| **标记符** | I | 命中后，你对该目标的下一次攻击骰池 +1 枚 | 无 |
| **攫取符** | I | 命中后可以夺取目标的一件手持物 | AP 消耗 +1 |

### 连锁类

| 符纹 | 等级 | 效果 | 代价 |
|---|---|---|---|
| **引爆符** | II | 命中已带状态的目标时，额外造成 2d6 伤害 | 专注消耗 +1 |
| **追猎符** | I | 命中后若目标移动，你可立即移动 3 米 | 无 |
| **回声符** | II | 若该能力本次判定落空，立即返还一半专注消耗 | 每场景只能触发一次 |
| **共感引爆符** | III | 当你对这个目标造成伤害时，所有处于同一状态的目标各受到一半伤害 | 应力 +2 |

### 代价类（强力但带副作用）

| 符纹 | 等级 | 效果 | 代价 |
|---|---|---|---|
| **献祭符** | I | 伤害 +4 | 自身承受 3 点不可减免伤害 |
| **透支符** | I | 本次判定骰池 +2 枚 | 场景结束时获得 2 点应力 |
| **缄默符** | II | 目标一回合内无法使用能力 | 你在自己的下个回合之前也无法使用能力 |
| **命运符** | III | 重掷整个骰池一次 | 永久 −1 活力上限（每个会话首次使用时生效） |

### 符纹等级限制

- **I 级符纹**：任何等级都可以安装。
- **II 级符纹**：需角色等级 ≥ 4。
- **III 级符纹**：需角色等级 ≥ 7。
- 同一个能力上**不能安装两枚同名或同类的符纹**（同类指同一分类，例如不能在一个能力上装两枚增幅类符纹）。

> 这条限制是为了让玩家在安装时必须考虑"这个能力的定位"，而不是无脑堆数值。

## 十一、附录：双引擎互转对照表

两套引擎**共用同一份内核**（属性定义、技能列表、状态、AP、破韧、连携、场地要素、资源框架）。因此一个角色、一个敌人、一个剧情，都可以在两套引擎之间迁移，而不必重建。

### 什么时候应该换引擎

| 情况 | 建议 |
|---|---|
| 团里有新玩家加入，且他对复杂数值有压力 | 战术 → 更简单，但如果是构建团，建议让他用预先配好的角色卡 |
| 大家觉得"每次都在掷同一个骰子，没变化" | 换构建引擎 |
| 大家觉得"每次都要数一堆骰子，太慢" | 换战术引擎 |
| 战役中途想换 | **建议等到章节分界点**，避免中途换算造成混乱 |
| 主持人是 AI 且上下文有限 | 战术引擎表达更紧凑，优先考虑 |

### 角色属性转换

属性的**值不变**，变的只是它被如何使用。

| 属性值 | 战术引擎用法 | 构建引擎用法 |
|---|---|---|
| 1–3 | 修正 −2 ~ −1 | 骰池枚数 = 属性（1~3 枚） |
| 4–5 | 修正 +0 | 骰池枚数 = 属性（4~5 枚） |
| 6–7 | 修正 +1 | 骰池枚数 = 属性（6~7 枚） |
| 8–9 | 修正 +2 | 骰池枚数 = 属性（8~9 枚） |
| 10 | 修正 +3 | 骰池枚数 = 10 枚 |

### 熟练与专精转换

| 项目 | 战术引擎 | 构建引擎 |
|---|---|---|
| 熟练（+2） | +2 固定加值 | 骰池 +1 枚 |
| 熟练（+3） | +3 固定加值 | 骰池 +2 枚 |
| 熟练（+4） | +4 固定加值 | 骰池 +2 枚，且该骰池整体骰阶 +1 |
| 专精 | 额外 +1，自然最高值时 +2 | 骰池额外 +1 枚 |

### 难度转换

| 战术 DF | 构建需求成功数 | 说明 |
|---|---|---|
| 6–8 | 1 | 平凡 |
| 10 | 2 | 简易 |
| 12 | 3 | 常规 |
| 14 | 4 | 有挑战 |
| 16 | 5 | 困难 |
| 18 | 6 | 严峻 |
| 20 | 8 | 极限 |
| 24 | 10 | 传说 |

> **中间的 DF**（如 13、15）在构建引擎里取较高的一档需求成功数，并给玩家 1 枚额外骰作补偿。

### 助势骰 ↔ 骰池

| 战术引擎 | 构建引擎 |
|---|---|
| 1 枚助势骰（+1d6） | 骰池 +1 枚 |
| 2 枚助势骰（+2d6） | 骰池 +2 枚 |
| 3 枚助势骰（+3d6） | 骰池 +3 枚 |
| 每层劣势（−1d6） | 骰池 −1 枚 |

> 战术引擎的一组助势骰期望约 +3.5；构建引擎的一枚 d8 期望约 +0.5 成功。二者并不等价，因此在转换时，资深导引者可以额外给 1 枚骰来补偿。

### 敌人防御转换

| 敌人的 Guard（战术） | 闪避需求成功数（构建） |
|---|---|
| 10–11 | 2 |
| 12–13 | 3 |
| 14–15 | 4 |
| 16–17 | 5 |
| 18 以上 | 6 |

### 伤害转换

战术引擎的攻击是"命中 → 掷一次伤害骰"；构建引擎是"成功数差值决定命中次数"。

| 战术结果 | 构建对应 |
|---|---|
| 暴击（超出 Guard 10+） | D ≥ +3，多次命中 |
| 重击（超出 6–9） | D = +2 |
| 命中（超出 0–5） | D = 0 ~ +1 |
| 擦过（低 1–2） | D = −1 |
| 落空（低 3+） | D ≤ −2 |

伤害骰本身保持不变（1d10 就是 1d10）。构建引擎只是把它乘上了命中次数。

### 迁移五步法

将一个进行中的角色迁移到另一套引擎：

1. **保留**六维属性值、背景标签、驱动、背景故事、关系网（这些与引擎无关）。
2. **重算**派生值：活力上限公式不变；构建引擎额外计算应力上限。
3. **重述**技能：把每项熟练换算为骰池枚数或固定加值。
4. **重述**能力：把伤害骰与效果保留，只是改变"如何判定成功"。
5. **符纹拆分**：若从构建引擎迁往战术引擎，把每枚符纹转化为一个等价的机动或专长。例如「强袭符」转化为一个专用机动：伤害 +3，但 AP 消耗 +1。

### 混用限制

- **同一个团的所有人应当使用同一套引擎**。混用会让导引者在不同角色之间来回换算，容易出错。
- **同一场战斗**中不允许部分人用 d20、另一部分人用骰池。
- **世界模组的内容两套引擎都可读**：三套世界观里的所有敌人、职途、能力与装备，都同时提供两套引擎所需的数值标注。
